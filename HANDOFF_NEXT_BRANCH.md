## 1. Сборка и запуск

**Приложение (Windows, .NET 8 SDK):** `run.bat` — двойной щелчок; `run.ps1` делает то же из PowerShell. Скрипт обновляет
клон с GitHub, собирает и запускает приложение.

- Аргументы передаются приложению: путь к `.p3d`, `--sample` (пробная деталь), `--theme light`.
- `-NoPull` — собрать без обновления.
- Если скрипт лежит не в клоне, он ищет клон в «Документы\parametric3d-rep» (OneDrive и папка профиля) или предлагает
  скачать.

Вручную: `dotnet build src/Parametric3D.csproj -c Release`. Пакеты (Avalonia 12.1.4, Svg.Controls.Skia.Avalonia,
CommunityToolkit.Mvvm, OpenTK.Mathematics) берутся с nuget.org.

Ключи приложения: `--mcp-stdio` (мост MCP, без окна), `--selftest`, `--shot <png> --script "<шаги>"` (снимок без
человека), `--gl` (выбор графики).

**Без сети (стенды ядра, Linux или Windows):**

```
dotnet build tests/k01/K01Checks.csproj -c Release -o out/k01 -p:LocalDeps=tools/deps
```

- В `tools/deps` лежат OTKMath (исходники OpenTK.Mathematics 4.9.4), SDCStub (заглушка System.Drawing) и NuGet.Config с
  пустым списком источников.
- Общее для проектов проверок — `tests/Directory.Build.props`. Исходники ядра по умолчанию — `../src`, иначе
  `-p:SourceRoot=<путь>`.
- Приложение без сети: `-p:LocalDeps=tools/deps -p:UiPackages=<каталог .nupkg Avalonia>`.

**Поставка:**

- `tools/make_package.sh <вывод> [RID]` (Linux) и `tools/make_package.ps1` (Windows) собирают переносную или
  самодостаточную поставку и проверяют её запуск.
- RID `portable` — одна сборка для Windows и Linux x64; запуск — `Parametric3D.cmd` или `Parametric3D.sh`.

## 2. Проверки

**Полная регрессия на своём компьютере** — `regress.bat` (двойной щелчок) или `.\regress.ps1`:

- `-Parallel` — этапы ядра одновременно (8+ ядер, 16+ ГБ памяти);
- `-Only allB|fix|allA|seq|ui` — один этап;
- `-NoPull` — без обновления.

Итог — `logs\regress_<дата_время>\SUMMARY.txt`: пройдено и провалено по этапам, имена провалов. Этот файл (или папку
логов zip-архивом) — в чат.

| Этап | Команда | Последний результат |
| --- | --- | --- |
| allB | `K01Checks allB` | 240/0 (k166–k167) |
| fix | `K01Checks loftcorpus140` | годны, 2 ожидаемых отказа фаски |
| allA | `K01Checks allA` | 414/0 (k165) |
| seq | `K01Checks loftseq 10 101 6 <каталог>` | 60/60 годны, точных 28 из 63 (k165) |
| ui | `Parametric3D.UiChecks "<UI-…|UI-…>"` (частями по 50) | 158/158 (k171) |

Перед прогоном: `DOTNET_TieredCompilation=0`, `P3D_USERMODELS=tests/ui/data` (модели пользователя). Проверки
приложения — `tests/ui` (Avalonia.Headless, без экрана); список имён — `Check("UI-…")` в `tests/ui/Program.cs`.

**Отдельные режимы `K01Checks`** (полный список — `tests/k01/Program.cs`):

| Режим | Что делает |
| --- | --- |
| `one <id>` | один сценарий |
| `guarantees`, `globals` | проверки G5/G6; опись изменяемых статических полей вне контекста |
| `allS` | обзор тел корпуса и долгая сессия KRN-11 (в `regress` не входит) |
| `perf [сценарий]` | замеры: медиана, p95, память, профиль; попеременное сравнение — `tests/perf_ab.sh` |
| `drawing155` … `drawing166`, `holes153`, `meshcut165` | наборы из allB по отдельности |
| `p3dprobe <файл>` | перестроение файла `.p3d` в отдельном процессе |
| `blendfile <файл>`, `blendedge <файл> <x,y,z,…> round|chamfer <r>` | разбор скругления или фаски на файле |

Диагностика маршрутов булевой — переменные `ANROUTE=1`, `GENCAPTURE=<причина>`, `GENVERIFY=1`.

**Сверка с OpenCascade:** `tools/occt_check.py`, `occt_diff.py`, `occt_mass.py`, `occt_time.py` (нужен pythonocc).

**Базовый прогон KRN-00** — `bash tools/run_baseline.sh <вывод>` (Linux): allA, allB, allS, g11poly, наборы A06
(`tests/run_local.sh`, `run_suites.sh`), сверка с OpenCascade, замеры, манифест. FProbe (`tests/fprobe`) из репозитория
убран: `tools/build_checks.sh` его не собирает, базовый прогон пропускает.

## 5. Порядок работы (как принято в репозитории)

1. Работа идёт по замечаниям пользователя. Каждое замечание — раздел в `BACKLOG.md` с пунктами `[ ]` и `[x]`; невыполненный
   остаток остаётся в разделе.
2. Каждое исправление закрепляется проверкой (`K01Checks` или `UI-…`) и мутацией `P3D_<ИМЯ>=0`, под которой проверка
   падает. В отчёте версии перечисляются мутации и их результат.
3. Публикация — один коммит в `main` на версию:
   - раздел `## kNNN (дата): …` в `CHANGELOG_K00_K10.md` — новые сверху в серии k, с отчётом по пунктам, проверками и
     строкой «Регрессия»;
   - строка сверху в таблице `VERSIONS.md`.
4. Регрессия: если ядро булевых не менялось, допустимо прогнать только затронутые наборы — с явной записью об этом в
   CHANGELOG (так сделано в k166–k171).
5. Отказ операции лучше неверного тела: если правильное построение не готово, операция отказывает с причиной (пример —
   фаска Sweep_Blend в k160).
6. Решения других ядер по разобранным случаям записываются в `REFERENCE_SOLUTIONS.md`.

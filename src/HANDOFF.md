## Как начать новый разговор

1. Загрузить **Parametric3D_handoff.zip** и этот файл.
2. Первым сообщением попросить: «Распакуй архив в /home/claude (src → /home/claude/src, build → /home/claude/build), прочитай HANDOFF.md и продолжай с этапа 2».
3. .NET 8 в среде может отсутствовать: `apt-get update && apt-get install -y dotnet-sdk-8.0` (nuget.org закрыт, пакеты не нужны).
4. Проверка, что среда жива: `cd /home/claude/build/Tests && dotnet build -c Release && dotnet bin/Release/net8.0/Tests.dll` → должно быть **«пройдено 69, провалено 0»**.
5. Прогон Verify запускать отвязанным процессом (иначе умирает вместе с командой): `setsid nohup dotnet bin/Release/net8.0/Parametric3D.Verify.dll --count 450 --seed 1 --out /tmp/vr > /tmp/vr.log 2>&1 < /dev/null &`. Не делать `pkill -f Verify` — убивает и саму оболочку.

## Проект

C# WinForms параметрический 3D-моделлер (net8.0-windows, OpenTK 4.9.4). Решение `Parametric3D.slnx`: приложение, `Parametric3D.Tests` (xUnit), `Parametric3D.Verify` (проверочный прогон).

Слои: `Core` (допуски, настройки) → `Kernel` (геометрия и топология) → `Model` (документ, детали, элементы дерева) → `Render` / `Views` / `UI` (OpenGL и WinForms).

### Ядро (Kernel)
- **Топология:** `TSolid` → `TShell` → `TFace` (поверхность `ISurface3`) → `TEdge` (кривая `ICurve3`) → `TVertex`.
- **Точная булева:** `Kernel/Exact/` — BSP на плоских многоугольниках в точной рациональной арифметике (плоскости в `PlaneRegistry`, сетка 1e-5 мм). `ExactAdapter.ToExact` (тело → многоугольники), `ExactBsp` (разбиение, локальная булева в коробке `LocalInBox`), `ExactMerge` (слияние кусков), `BooleanOp.FromPolygons` (многоугольники → тело: грани по меткам, рёбра, восстановление дуг `MergeArcs`, кривых пересечения).
- **Поверхности:** `PlaneSurface`, `ExtrudedSurface` (профиль × направление), `RevolvedSurface`, `CylinderSurface`, `FacetedSurface` (треугольники + `Source` — исходная поверхность; нормали вершин кэшируются на поверхность), **`SectionSurface`** (новое, этап 2: поверхность по сечениям — отрезок фаски или дуга скругления в каждом сечении; процедурный режим — сечение по формуле при параметре хребта u = длина дуги цепочки в мм, с продлениями [−ext0, 0] и [L, L+extL]; запасной — линейно между сечениями; точная проекция: затравка по плотной сетке проб формулы (шаг по u ≤ ¼ ширины сечения, три затравки из разных мест) + Гаусс — Ньютон). **`SectionIsoCurve`** — изолиния v = const (линия касания скругления, край фаски): точное ребро шва, где кривая пересечения касающихся поверхностей не уточняется; отход вершин тела распределён вдоль кривой линейно.
- **Кривые:** `LineCurve3`, `ArcCurve3`, `IntersectionCurve3` (процедурная кривая пересечения; затравка точки — с уже уточнённых точек, последняя точка запоминается), `CurveParam.Closest` (точный ближайший параметр). `ExactSurfaces.ProjectUnsigned` — проекция без согласования знака нормали (дешевле у цилиндра).
- **Рёбра результата булевой (`BooleanOp.MergeArcs`):** цепочка между двумя гранями с точными поверхностями раскладывается `LinesAndCurves`: прямая — наибольший отрезок цепочки (не короче 0.05 мм), лежащий на обеих поверхностях (допуск 2e-5 — сетка ядра); участки между прямыми — дуга (по точкам или по уточнённым точкам кривой пересечения) либо кривая пересечения. Вся цепочка одной прямой — один отрезок. Порядок распознавания участка: дуга по точкам → изолиния процедурной поверхности → кривая пересечения; изолиния или кривая, легшая на окружность, становится дугой (`ArcIfRound`). Кольцо (начало = конец), не легшее на окружность, делится натрое кривыми пересечения; короткое кольцо (< 9 звеньев) остаётся хордами. У резцов (`SolidFromPolygons(polys, sources)`) точные рёбра не ищутся.
- **Скругления и фаски:** `Kernel/Ops/FilletOp.cs` — специальные построители резцов (прямая между плоскостями, дуга на плоскости со стенкой цилиндра, прямая вдоль образующей цилиндра, вогнутые — прибавка) и **протянутый резец** `BuildSweptChamfer(..., round)` для цепочек, которые специальные не берут (кривые, кривые грани), и для гладких цепочек дуг+прямых у фаски. Все грани резца несут точные поверхности: рабочая полоса — процедурная `SectionSurface` (`SweptWorkingSurface`, сверка формулы с сечениями резца, расхождение ~5e-6), вспомогательные полосы — `SectionSurface` по отрезкам, торцы — плоскости. **Выбор режется в изломах на гладкие участки** (`SmoothPieces`: рёбра объединяются, только если в вершине их два и излом по точным касательным `TangentOutOf` меньше 10°); каждый участок — свой резец (протянутый или специальный), углы проходят продления концов. Проверка самопересечения резца: отрезок пересекает треугольник, только если концы по разные стороны плоскости с запасом (компланарные соседи на прямых участках давали ложный отказ). Перед резом резец проверяется (складка — по весу отрицательных отрезков, самопересечение). Защитная проверка `Damage` после каждого реза, откат при порче.
- **Экспорт:** `Kernel/Export/MeshExport.cs` — STL (двоичный/текстовый), OBJ, гранёный STEP AP214 (проверен OpenCascade: `pip install cadquery-ocp`).

### Приложение
- Пересборка модели в фоне: `Part.Compute/Apply`, `Document.RebuildDirtyAsync`, правка заперта на время расчёта (`IsBuilding`).
- Выбор цепочек рёбер: `Kernel/Topology/EdgeChain.cs` (порог излома 10°; рёбра между одной парой граней в вершине степени 2 — продолжение при любом угле).
- Отрисовка линий: `Render/Shaders.cs` (обрезка по ближней плоскости и по окну; удлинение отрезков только на стыках ломаной, флаги 8/16 в `LineBatch`).
- Контекст сборки/детали: `RenderScene.ActiveOwner`, `ScenePicker.ActiveOwner` — чужие плоскости и точки начала бледнее и с пониженным приоритетом выбора.

## Среда сборки под Linux (/home/claude/build)
WinForms здесь не собирается. Поэтому:
- `Tests/` — консольный запуск тестов ядра (облегчённая замена xUnit `XunitShim.cs`, `Runner.cs` с ключами-сценариями `--rim`, `--rq R`, `--exactrim` и т.п.). Компилирует `src/Core`, `src/Kernel`, тесты и часть Verify.
- `Verify/` — проверочный прогон: `dotnet bin/Release/net8.0/Parametric3D.Verify.dll --count 450 --seed 1 --out /tmp/vr` (ops-*.csv, summary.md), `--replay SEED`, `--inspect SEED STEP`.
- `ModelCheck/` — смысловая сборка слоя `Model` (заглушка `Settings`).
- `Syntax/` — проверка синтаксиса отдельных файлов UI/Render: `dotnet Syntax/bin/Release/net8.0/Syntax.dll файл.cs`.
- Файлы UI, Render, Views и шейдеры **проверяются только синтаксически** — пользователь проверяет у себя.

## План «точная поверхность — хозяин грани» (согласован с пользователем)
1. **Точная геометрия поверхностей — СДЕЛАНО.** Точные `ProjectToUV` у выдавливания и вращения; тест `Surface_projection_is_exact`.
2. **Грань = точная поверхность + граница из точных рёбер — СДЕЛАНО.** Грани протянутого резца несут `SectionSurface`; кромки раскладываются на прямые, дуги и кривые пересечения по точным поверхностям. Остаток: `FacetedSurface` с `Source == null` в коде ещё обрабатывается (для старых тел), но новые операции таких граней не дают.
3. **Гранение из точной геометрии.** Рёбра гранятся один раз и делятся соседними гранями (сетка без щелей по построению), триангуляция в параметрах поверхности; треугольники после булевой — промежуточные.
4. **Операции на точной геометрии.** `FilletOp` (12 мест с `.Facets`), `BooleanOp` (5), проверки Verify — точки и нормали у поверхностей.
5. **Процедурные поверхности скругления и фаски** (шар по точным поверхностям, линии касания — кривые пересечения смещённых поверхностей) — уберёт зубцы и «кромки отрывками» у протянутого скругления по кривой кромке (последняя жалоба пользователя, снимок: край отверстия после фаски, скругление R5).

Отвергнутое на пути к п.5 (не повторять): качение шара по треугольникам граней и деление промежутков пополам для расстановки сечений — резец вылезал в тело и налезал сам на себя.

## Уроки, которые дорого обошлись
- **Менять геометрию ради вида нельзя** — вид чинится нормалями.
- **Проверка должна мерить то, что видит пользователь** (рёбра, цепочки, закраска), а не только замкнутость.
- **Каждое исправление — на сцене пользователя**, а не на похожей: дважды «исправил» не тот случай.
- **Прогон ловит то, что тесты не видят** — после каждого изменения ядра прогонять Verify.
- **Шкала готовности:** в ответах давать % близости к промышленному ядру (сейчас ~18%) — пользователь просил.
- **Точные поверхности дороги, если гранить их в лоб:** первая версия этапа 2 замедлила прогон в 50 раз (проекция на каждую вершину при каждом гранении). Кэш нормалей, нормаль на вершину, затравка по сетке — и время вернулось к базовому. После изменения ядра смотреть и время прогона, не только сбои.
- **Параметр процедурной поверхности — по длине дуги:** номер ребра как параметр давал скачок скорости на стыках (ребро → продление), и Ньютон застревал.
- **Направление ребра на конце — только по точной касательной:** разность «точка через 1e-4 минус вершина» у кривой пересечения даёт случайный излом (вершина на сетке, точка уточнена).
- **Затравка проекции — по плотной сетке самой формулы:** сечения резца на прямых участках стоят через десятки мм, и ближайшая проба оказывалась в чужом месте.
- **Распознавание по точной поверхности должно учитывать масштаб:** короткое звено «лежит» на любой поверхности; прямая — только заметной длины и как наибольший отрезок, а не по звеньям.
- Код отдаётся архивом изменённых файлов с путями от корня проекта.

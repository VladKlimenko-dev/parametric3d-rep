## Цели, принципы и требуемый результат

Цель — параметрическое B-rep ядро промышленного уровня: форма задаётся точными поверхностями, каждая операция либо даёт годное тело с явным уровнем гарантии, либо честно отказывает с причиной.

**Требуемый результат** (критерии готовности, по которым шла работа):

1. Точность: объём и геометрия тел — по точным поверхностям (ошибка порядка 1e-11 мм³ там, где формула известна), гранение — только для экрана и STL/OBJ.
2. Гарантии: опубликованное тело неизменяемо; нет изменяемого глобального состояния вне контекста; негодный результат не принимается молча.
3. Воспроизводимость: одинаковый вход — побитово одинаковый результат (детерминированные алгоритмы, без случайности и зависимости от порядка хеширования).
4. Скорость: полное перестроение реалистичной детали — сотни миллисекунд, правка последней операции — десятки (с переиспользованием сеток).
5. Возможности: выдавливание, вращение, булевы, отверстия, скругления, фаски, вершинные операции, оболочка, уклон, ребро, лофт, протяжка, массивы, обмен STEP/IGES.

**Принципы устройства:**

- Несколько маршрутов булевой по убыванию точности: 2.5-мерный аналитический → общий аналитический → многогранный (точная рациональная арифметика). Каждый маршрут проверяет свой результат; при отказе работает следующий.
- Уровень гарантии на теле: `ExactAnalytic` (точные поверхности), `ExactPolyhedral` (точные рациональные предикаты над многогранником — НЕ аналитическая точность формы: цилиндр в нём гранёный), ниже — приближённые.
- Настройки ядра — снимок контекста `KernelContext`; глобальные значения меняются только вне контекста (проверка G5).
- Каждое исправление закрепляется проверкой; сравнение с прошлым состоянием — запись в запись по журналам корпуса.
- Независимые проверки вместо самопроверок: сверка объёма операнда с независимым расчётом, согласие результата с CSG по точкам.

## Архитектура ядра

Ядро устроено слоями: операции моделирования строят резцы и отдают их булевой, а булева выбирает аналитический или многогранный путь над общей основой топологии и геометрии.

Схема (сверху вниз; стрелки — «вызывает»):

```
Приложение (src/UI, src/Render) — WinForms + OpenGL
   MainForm, диалоги операций, дерево проекта; рисует сетки отображения опубликованных тел
        ↓
Модель детали (src/Model)
   Part: AddFeature, Rebuild, Compute/Apply; операции детали; FeatureHistory — устойчивые имена граней
        ↓
Операции моделирования (Kernel/Ops)
   ExtrudeOp, RevolveOp, LoftOp, SweepOp, RibOp, ShellOp, DraftOp, TransformOp
   FilletOp (скругления, фаски), VertexOp, QuadricCut и CrossHole (отверстия)
        ↓
BooleanOp — маршруты булевой
   по очереди: 2.5-мерный → общий аналитический → многогранный; каждый проверяет свой результат
        ↓                                         ↓
Аналитическое ядро (Kernel/Analytic)        Точное многогранное (Kernel/Exact)
   Region2, Prism25, PrismBuild — этап 1       рациональная арифметика, ExactBsp,
   Classifier, FaceIntersect, FaceSplit,       PlaneRegistry, ExactAdapter.ToExact;
   GeneralBoolean — этап 2                     запасной путь и ленивая форма тел
        ↓                                         ↓
Основа: топология и геометрия
   Topology: TSolid … TVertex, TopologyConventions, SolidValidator, AnalyticVolume
   Surfaces (плоскость, выдавливание, вращение, NURBS), Curves (дуги, эллипсы, трассы), Ssi
        ↓                                         ↓
Разметка (Kernel/Tess)                      Обмен (Kernel/Export)
   ExactFaceMesher, UvMesher, Triangulator, CDT   STEP точный и гранёный, IGES, STL, OBJ
```

Разметка даёт сетки отображения, которые рисует приложение; точное многогранное ядро также строит производную форму аналитических тел, когда следующая операция уходит многогранным путём. Объём: ядро ~45 800 строк (Ops 12 800, Tess 9 300, Exact 4 900, Topology 4 900, Export 3 200, Analytic 3 100).

## Функции ядра

Ядро покрывает полный цикл твердотельного моделирования детали: построение тел, булевы, модификацию кромок и вершин, историю и обмен.

| Группа | Что умеет | Ключевые классы и методы |
| --- | --- | --- |
| Топология B-rep | Тело → оболочки → грани → контуры → полурёбра → рёбра → вершины; соглашение о полурёбрах, клонирование, проверка, лечение | `TSolid`, `TFace`, `TEdge` (`Topology.cs`), `TopologyConventions.Normalize`, `TopologyClone.Deep`, `SolidValidator.Validate/ValidateBRep/ValidateMesh`, `TopologyHeal` |
| Поверхности | Плоскость, выдавливание кривой, вращение, NURBS, смещённая, гранёная (сетка с точным источником) | `PlaneSurface`, `ExtrudedSurface`, `RevolvedSurface`, `NurbsSurface`, `OffsetSurface`, `FacetedSurface` |
| Кривые | Отрезок, дуга, эллипс, сплайн, кривая пересечения (трассировка) | `LineCurve3`, `ArcCurve3`, `EllipseCurve3`, `SplineCurve3`, `IntersectionCurve3` |
| Пересечения | Пересечение поверхностей: прямые, окружности, эллипсы, кривые 4-й степени; распознавание вида поверхности | `Ssi.Intersect/Trace`, `ExactEdges.ShapeOf` |
| Примитивы и построение | Цилиндр, конус, сфера, тор; эскиз-профиль; выдавливание, вращение, лофт, протяжка, ребро жёсткости | `PrimitiveOp`, `ProfileBuilder.Build`, `ExtrudeOp`, `RevolveOp`, `LoftOp`, `SweepOp`, `RibOp` |
| Булевы | Объединение, вычитание, пересечение — три маршрута | `BooleanOp.Unite/Subtract/Intersect/Evaluate` |
| Аналитическое ядро | 2D-булевы с дугами, 2.5-мерные тела по слоям, классификатор точки, пересечение и разбиение граней, общая булева | `Region2Ops`, `Prism25`, `PrismBuild`, `Classifier`, `AnalyticFace`, `FaceIntersect`, `FaceSplit`, `GeneralBoolean` |
| Точное многогранное ядро | Рациональная арифметика, дерево разбиения пространства, реестр плоскостей, точный ввод цилиндра и плоских граней, квадрики | `ExactBsp`, `ExactAdapter.ToExact`, `PlaneRegistry`, `ExactPlanarInput`, `ExactCylinderInput`, `QBoolean`, `Quadric*` |
| Отверстия | Сквозные, глухие, цекование, зенковка, поперечные; точные маршруты | `QuadricCut.Cut/CutBlind/CutCounterbore/CutCountersink`, `CrossHole.Cut` |
| Кромки и вершины | Скругление (постоянное, переменное, катящийся шар), фаска, скругление и фаска вершины | `FilletOp.RoundEdges/RoundEdgesVariable/ChamferEdges`, `VertexOp.Round/Chamfer` |
| Прочие операции | Оболочка, уклон, перемещение, поворот, зеркало, массивы | `ShellOp.Hollow`, `DraftOp.Apply`, `TransformOp.Move/Rotate/Mirror/LinearPattern/CircularPattern` |
| Сетки | Разметка граней (точная по контурам, в развёртке, кольцами к полюсу), триангуляция с отверстиями, CDT, переиспользование сеток при правках | `ExactFaceMesher`, `UvMesher`, `Triangulator`, `Cdt`, `BooleanOp.MeshExactlySolid/UseMeshDonors` |

| Модель детали | Дерево операций, перестроение (полное и с правки), история граней, устойчивые имена граней | `Part.Rebuild/Compute/Apply`, `FeatureHistory`, особенности в `Model/Features` |

## Маршруты булевой и уровни гарантии

Ядро одно (одна модель B-rep, один интерфейс), но у булевой пять путей выполнения, и ядро выбирает их само для каждой операции: точные пути отверстий — до булевой, затем внутри булевой по убыванию точности 2.5-мерный аналитический, общий аналитический, многогранный точный и, только при явно разрешённой политике, приближённый.

```
Отверстие (HoleFeature): свои точные пути — до булевой                 —принят→ ExactQuadric или ExactPolyhedral
   quadric-through/blind (QuadricCut), exact-blind,
   exact-cut-edge-blind (ExactCylinderCut), cross-hole
  ↓ не подошли (или не отверстие)
BooleanOp.Evaluate (тело, резец, вид, политика)
  ↓
1. 2.5-мерный аналитический — 70.5 % решений                         —принят→ ExactAnalytic (точные поверхности)
   Оба тела — призмы вдоль общего направления; булева сечений по слоям,
   сборка B-rep из точных плоскостей и цилиндров.
   Проверки: объём операндов независимо, разметка всех граней, B-rep.
  ↓ отказ
2. Общий аналитический — 9 % решений                                  —принят→ ExactAnalytic (точные поверхности)
   Плоскости, цилиндры, конусы (сферы — флаг); пересечение и разбиение граней,
   отбор областей, сшивка, слияние.
   Проверки: разметка, B-rep, согласие с CSG по 256 точкам.
  ↓ отказ
3. Многогранный точный — остальное                                    —принят→ ExactPolyhedral (точный многогранник)
   Рациональная арифметика, дерево разбиения пространства;
   аналитические операнды — по их ленивой форме (грубая).
   Проверки: замкнутость точной формы, B-rep, сетка.
  ↓ отказ
4. Приближённый (Csg, двойная точность)                               —принят→ Approximate (тело помечено)
   Только при политике AllowApproximate; строгая политика
   (по умолчанию) сюда не пускает — сразу отказ.
  ↓ отказ
Отказ операции с причиной (состояние детали не меняется)
```

| Путь | Где в коде | Когда работает | Уровень гарантии |
| --- | --- | --- | --- |
| Точные пути отверстий | `HoleFeature` → `QuadricCut`, `ExactBoolean.SubtractBlindCylinder`, `ExactCylinderCut`, `CrossHole` | Операция «отверстие» пробует их по очереди до булевой; не подошли — общая булева (`general-boolean`, в том числе составной резец) | `ExactQuadric` или `ExactPolyhedral` |
| 2.5-мерный аналитический | `Kernel/Analytic`: `Prism25`, `PrismBuild` | Оба тела — призмы вдоль общего направления (~70 % решений) | `ExactAnalytic` |
| Общий аналитический | `Kernel/Analytic`: `GeneralBoolean` | Плоскости, цилиндры, конусы любых направлений (~9 %) | `ExactAnalytic` |
| Многогранный точный | `Kernel/Exact`: рациональная арифметика, `ExactBsp` | Всё остальное: сферы, торы, касания, отказы аналитических путей | `ExactPolyhedral` |
| Приближённый | `Ops/Csg.cs`, этап `boolean.approximate` (двойная точность) | Точный путь не справился и политика операции — `AllowApproximate` | `Approximate`, статус `SucceededApproximate` |

Политика ГЕОМЕТРИИ (KRN-01) — `GeometryPolicy.AllowBoundedFaceting` (по умолчанию) или `PreserveBRep`: во второй
многогранный и приближённый пути дают отказ `Unsupported` (geometry-downgrade-refused), в первой понижение аналитического
операнда до фасет записывается в диагностику (geometry-downgrade). Исход операции типизирован (`OperationResult.Outcome`:
Success, Empty, Unsupported, InvalidInput, AccuracyExceeded, Cancelled, InternalFailure).

Политика арифметики — `OperationPolicy.Strict` (по умолчанию) или `AllowApproximate`. Строгая отказывает, если точный маршрут пришлось подменить приближённым и если приближённым был сам операнд; приближённая принимает подмену, но помечает тело. Потерю грани при гранении, исключение и негодную топологию не принимает ни одна: это брак, а не приближение. Отдельно от путей построения — `Kernel/Voxels`: классификация точки по сетке и аудит булевых, только для проверок.

Аналитический результат несёт ленивую производную многогранную форму: она строится, только если следующая операция уйдёт многогранным путём; у этапа 1 она точная (плоскости и треугольники по точкам рёбер), у этапа 2 — из сетки отображения, отсюда проблема смешанных цепочек. Имена граней наследуются от операндов на любом маршруте; сетки неизменённых граней переиспользуются по строгому ключу (поверхность и контуры побитово). Внедрённый сбой или исключение в аналитическом маршруте = отказ маршрута; отмена пробрасывается сразу.

## Совместимость с приложением

Приложение работает с ядром через модель детали: оно добавляет операции, вызывает перестроение и рисует опубликованные тела по их сетке отображения; аналитические маршруты ядра на этот интерфейс не повлияли.

- **Сборка:** приложение — `Parametric3D.csproj`, `net8.0-windows`, WinForms + OpenGL; ядро и модель лежат в том же проекте (`src/Kernel`, `src/Model`). Стенды проверок собирают ядро под Linux без интерфейса.
- **Вызовы из интерфейса:** `part.AddFeature` (5 мест), `part.Invalidate` (11), `part.Rebuild` (2) в `UI/MainForm.cs` и `UI/FeatureDialogs.cs`; модель внутри использует `Part.Compute/Apply` (вычисление отдельно от публикации).
- **Тела:** `Part.Bodies` — опубликованные `TSolid`, неизменяемые (запись в опубликованное тело отвергается); отрисовка берёт `FacetedSurface.Display` каждой грани (треугольники и нормали — одна атомарная ссылка).
- **Обмен в интерфейсе:** STL (текст и двоичный), OBJ, STEP — **только гранёный** (`MeshExport.WriteStepFaceted`). Точный экспорт ядра (`StepExact.Write`, точные окружности и прямые) и IGES из интерфейса не вызываются — это незадействованная возможность.
- **Не проверено:** сборка и запуск приложения под Windows в этой среде невозможны (Linux); пункт за владельцем.

Настройки ядра — снимок `KernelSettings` в `KernelContext`; значения по умолчанию задаются переменными окружения при запуске:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `P3D_ANALYTIC` | вкл. (`=0` — выкл.) | 2.5-мерный аналитический маршрут булевой |
| `P3D_ANALYTICGENERAL` | вкл. (`=0` — выкл.) | Общая аналитическая булева (плоскости, цилиндры, конусы) |
| `P3D_ANALYTICSPHERES` | выкл. | Сферы в маршруте общей булевой (по умолчанию для `KernelSettings.AnalyticSpheres`) |
| `P3D_CAPBYLOOP`, `P3D_BNDCUT`, `P3D_POLECUT`, `P3D_POLESLIVER`, `P3D_SHELLFIX`, `P3D_POLELIMIT`, `P3D_STEREOMESH`, `P3D_POLEDROP`, `P3D_SPHPOLE=facets`, `P3D_SPHAXIS=rule|keep`, `P3D_MATSIDEMID`, `P3D_FULLTORUS` | вкл. | KRN-03: переключатели мутационной проверки (0 — прежнее поведение) |
| `P3D_GENTANGENT` | выкл. | Касания поверхностей в общей булевой (разбор) |
| `P3D_NOOVERLAP` | выкл. | Резцы скругления без перехлёста на общих концах (эксперимент) |
| `P3D_LAZYFINE` | выкл. | Мелкая ленивая многогранная форма (эксперимент) |
| `P3D_MESHREUSE`, `P3D_CHORD`, `P3D_CHORDANG` | см. код | Переиспользование сеток, допуск хорды и угла разметки |

Прочие переменные (`P3D_QCUT`, `P3D_QHOLE`, `P3D_HEAL`, `P3D_SNAPV`, `P3D_THREADS` и др.) управляют частными маршрутами и диагностикой; список — в коде (`grep P3D_`).

## Текущие проблемы и ограничения

Главная проблема — смешанные цепочки: когда за аналитическим результатом следует операция многогранного пути, она работает по грубой производной форме, и в цепочках скругления это даёт ошибки, которые аналитический путь сам не делает.

| # | Проблема | Причина | Проявление |
| --- | --- | --- | --- |
| 1 | Смешанные цепочки скругления | Ленивая многогранная форма результата общей булевой строится из сетки отображения (хорда 0.02 мм, шаг 7.5°) | С флагами сфер и касаний: скругление 12 рёбер — объём −14 мм³ (2.9e-4), сетка 16–20 замечаний; в 3.3 раза мельче — проходит, но вдвое дольше |
| 2 | Резцы скругления рассчитаны на многогранный путь | Перехлёст соседних резцов на общем конце 0.001 мм (`FilletOp.ClaimedOverlap`) | Для точного ядра — щели шириной 0.001 мм; без перехлёста ломается многогранный путь (призма — 16 замечаний) |
| 3 | «Грязная» геометрия на входе общей булевой | Тела из многогранного пути: восстановленные кривые расходятся с вершинами до 0.004 мм, микрорёбра | «Нет точки внутри области», негодные результаты (отклоняются проверками) |
| 4 | Сфера и касания не в маршруте по умолчанию | Пп. 1–3: включение ломает 2–3 проверки корпуса | 53 + 26 булевых allB идут многогранным путём |
| 5 | Тор не поддержан общей булевой | Нет параметризации и разбиения граней тора | 7 булевых allB (+ угловые сопряжения скруглений) |
| 6 | Вложенные и непересекающиеся тела | Общая булева требует пересечения граней; нет многооболочечного результата | 5 булевых allB — многогранным путём |
| 7 | Пропуск коротких участков пересечения | Кривая пересечения сэмплируется (≥ 256 точек, 20 на мм) | Теоретический риск; проверка согласия с CSG ловит лишь заметные расхождения |
| 8 | Конус: искажение расстояний | Развёртка (θ·R, h) с одним опорным радиусом; вершина конуса — особая точка | Допуски у границы неточны до 2–3 раз; нет проверки грани с вершиной |
| 9 | Объём сферической грани с дугами | Интегратор считает такую грань по ломаной | Вырез угла сферой — 1.4e-3 мм³ (3e-8 отн.) |
| 10 | Дерево разбиения многогранного пути у почти выпуклых резцов | Квадратичная цена разрезания цепочки | Сферический вырез ~200 мс из ~550 |
| 11 | Приложение | Windows-сборка не проверялась в этой среде; точный STEP и IGES не выведены в интерфейс | Пользователь получает только гранёный STEP |
| 12 | Технический долг | Отладочные крючки и флаги экспериментов (`GENCAPTURE`, `GENVERIFY`, `P3D_GENTANGENT`, `P3D_NOOVERLAP`, `P3D_LAZYFINE`) | Усложнение кода; все флаги — неизменяемые, по умолчанию выключены |

## Варианты решений и рекомендации

Рекомендация: зафиксировать стабильное ядро r54 и решать проблему скруглений не правками маршрутов, а прямым аналитическим построением скругления — это устраняет причину смешанных цепочек, а не её следствия.

| Направление | Варианты | За | Против |
| --- | --- | --- | --- |
| Скругления (пп. 1–4) | **А.** Прямое аналитическое построение: поверхность скругления (цилиндр, тор, сфера сопряжения) строится и обрезается по линиям касания, без вычитания резца | Убирает причину смешанных цепочек; так делают промышленные ядра; точный результат | Большой этап, сопоставим с этапом 2а (общая булева) |
| | **Б.** Точечно мелкая ленивая форма — только для граней, которых касается резец следующей операции | Дешевле равномерного измельчения | Компромисс; не лечит п. 2 и п. 3 |
| | **В.** Остановиться: скругления — многогранным путём, как сейчас | Ничего не ломает | Точность скруглений — уровня многогранного пути |
| Тор (п. 5) | Параметризация (θ, φ) с двумя периодами, разбиение в развёртке | Закрывает угловые сопряжения и скруглённые кромки отверстий | Два периода — сложнее цилиндра |
| Вложенные тела (п. 6) | Классификация одной точки каждого тела; многооболочечный результат | Небольшой объём | Нужна поддержка нескольких оболочек в сборке |
| Короткие участки (п. 7) | Концы участков — решением «кривая = граница грани» для каждого ребра (как уточнение концов), без сэмплирования | Точно | Комбинаторика пар «кривая × ребро» |
| Конус (п. 8) | Метрика развёртки по месту (r(h) вместо R); отдельная проверка вершины | Точные допуски | Мелкая доработка |
| Приложение (п. 11) | Вывести точный STEP (`StepExact.Write`) и IGES в меню экспорта; проверить сборку под Windows | Пользователь получает точную геометрию | Нужна Windows-среда |
| Технический долг (п. 12) | Убрать флаги экспериментов, оставив выводы в документах | Проще код | Теряется быстрое воспроизведение разборов |

Рекомендуемый порядок:

1. Приложение: точный STEP и IGES в меню, проверка под Windows — дёшево и сразу полезно.
2. Вложенные тела и метрика конуса — небольшие доработки общей булевой.
3. Этап «аналитические скругления» (вариант А) вместе с тором.
4. После этапа 3 — включить сферы и касания по умолчанию и снять флаги экспериментов.

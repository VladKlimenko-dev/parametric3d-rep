# Скорость ядра: замеры, причины, сравнение с промышленными ядрами, план (KRN-10)

Дата: 2026-10-11. Машина: 2 ядра, Linux, .NET 8, `DOTNET_TieredCompilation=0`. Все числа — замеры этой ревизии;
инструменты в поставке: `K01Checks holes <N> [cyl|box|pocket|sphere]` (ядро: пластина и N вычитаний), `K01Checks
partholes <N>` (деталь: N операций «отверстие», полное перестроение), `K01Checks speed <seed> <n…>` (пластины K08),
`DIFFPROF=<файл> K01Checks diffdump …` (время и этапы каждой случайной цепочки).

## 1. Что измерено

### 1.1. Случайные булевы (серия 8, 200 цепочек, 285 операций)
| Маршрут | Операций | Медиана | p90 | Максимум | Сумма |
|---|---|---|---|---|---|
| Точный аналитический (плоскость, цилиндр, конус, шар) | 139 | 0.10 с | 0.40 с | 3.1 с | 25 с |
| Многогранный (тор, касания, многогранный операнд) | 146 | 1.9 с | 5.0 с | 15.7 с | 350 с |

Этапы многогранного маршрута (сумма по серии, включительно): разбиение пространства в рациональных числах 118 с;
разметка граней тора 95–101 с (из них поиск ориентации 50 с); сборка тела из многоугольников (FromPolygons) 69 с;
разметка граней по точной геометрии 66 с. Выделения памяти — 170–340 МБ на одну булеву.

### 1.2. Деталь из N однотипных операций (пластина и N отверстий, полное перестроение)
| N | до правок | после правок |
|---|---|---|
| 32 | 2.3 с | 0.32 с |
| 64 | 7.8 с | 1.06 с |
| 96 | 21.4 с | 2.1 с |

До правок рост был сверхквадратичным: удвоение N — время ×4.8. Сама операция «отверстие» стоит 3–5 мс и почти не
зависит от N; остальное — накладные расходы дерева на операцию, пропорциональные размеру ВСЕГО тела:
- история (`FeatureHistory.Between`) сравнивала каждую группу граней с прежней ПО СЕТКЕ (разметка всех граней тела после
  каждой операции): 82% времени, 4.2 ГБ выделений на 48 отверстий;
- нормализация соглашения о полурёбрах (`TopologyConventions`): роль кольца (вложенность) пересчитывалась для каждой
  компоненты с повторной разметкой всех колец грани — у плиты с 96 отверстиями 97×97 разметок колец на операцию, 3.2 ГБ;
- подписи граней и рёбер, аудит геометрии — каждый раз по всему телу.

### 1.3. Ядро: N вычитаний подряд (без дерева)
Время одного вычитания растёт линейно с числом граней тела: 8 мс при 9 гранях, 534 мс при 102 гранях. Основное —
«завершение»: аналитическая булева размечает (сетка показа) ВСЕ грани результата, нормализует всё тело, проверяет
сетку целиком, а общий маршрут ещё и классифицирует 256+ точек тремя классификаторами.

## 2. Как это устроено у промышленных ядер (Parasolid, ACIS, CGM, OpenCascade)
| Механизм | Промышленные ядра | Parametric3D |
|---|---|---|
| Локальность булевой | Пары граней — по иерархии габаритов (BVH); режутся только пересекающиеся грани, прочие классифицируются по связности и переходят в результат теми же объектами | Тело копируется целиком; нормализация, разметка, проверка — по всему телу |
| Неизменяемость и откат | Правка на месте с журналом отката (partition/rollback marks Parasolid, BRepTools_History/Undo OCCT): стоимость — размер изменения | Опубликованные тела заморожены, операция работает с глубокой копией: O(размер тела) на операцию, все кэши граней теряются |
| История и происхождение | Выход самой операции (OCCT: Modified/Generated/IsDeleted у каждого алгоритма; Parasolid: отслеживание сущностей) | Восстанавливается после операции сравнением граней (с этой поставки — по точным подписям, без сетки) |
| Тесселяция | Отдельно от моделирования, лениво, кэш на грань, инвалидируется только у изменённых граней | Аналитическая булева размечает все грани результата на каждой операции; дерево — ещё раз в конце |
| Арифметика | Плавающая точка с допусками; точные предикаты только с фильтром (адаптивные, интервальные) | Многогранный маршрут — рациональные числа (BigInteger) во всём разбиении; аналитический — double |
| Тор, сплайны | Аналитическое пересечение (маршевое прослеживание), без перехода к фасетам | Тор — многогранный маршрут: гранение, рациональное разбиение, разметка; на порядок дороже |
| Самопроверка операции | Инварианты гарантирует алгоритм; полная проверка тела — по запросу | Каждая операция проверяет результат (B-rep, сетку, p-кривые, согласие с CSG по точкам) |

Последняя строка — сознательное различие: самопроверка — источник надёжности этого ядра (0 неверных на 600 случайных
цепочках). Её не убирать, а делать дешевле (локально, по изменённым граням).

## 3. Что сделано в этой поставке (с мутациями)
- История: побитовая подпись группы граней (поверхность по содержанию, кривые всеми определяющими числами, направления
  полурёбер, сторона грани) — доказательство тождества при ЛЮБОМ уровне гарантии; у плоских граней разное число контуров —
  доказательство различия. Сравнение по сетке остаётся последним средством (на детали с отверстиями — 0 раз).
  `P3D_HISTSIG=0`.
- Нормализация: точки колец, роли, габариты — один раз за проход; быстрый отказ «точка в многоугольнике» по габариту.
  `P3D_CONVCACHE=0`.
- Подписи граней и рёбер — кэш на объект грани с ревизией тела. `P3D_HISTCACHE=0`.
- Проверка `KRN10-TREE-OVERHEAD-NOT-QUADRATIC` (по счётчикам, не по времени): история решается без сетки; рост числа
  разметок колец при 3× операций — не больше 12×; подпись считается не больше 0.6 запросов. Каждая мутация ловится.

## 3а. Тор в точном маршруте (сделано 2026-10-11)
Серия 8 (200 цепочек, 285 операций), только построение (без OpenCascade), один прогон, машина свободна:
| | Без тора в точном маршруте | С тором |
|---|---|---|
| Время серии | 652 с | 337 с |
| Точных операций | 139 (сумма 22 с) | 217 (сумма 50 с, медиана 0.17 с) |
| Многогранных операций | 146 (сумма 300 с, медиана 1.6 с) | 68 (сумма 140 с, медиана 1.7 с) |
Серии 8–10: точный итог у 402 цепочек из 549 непустых (прежде 260). Оставшиеся многогранные — смешанные постройки (брусок/шар/
цилиндр с тором, конусы); причины отказа точного маршрута по операциям собираются `DIFFWHY=<файл> K01Checks diffdump`.

## 3б. Отказы точного маршрута (2026-10-11)
Причина отказа на каждую операцию — `DIFFWHY`. Исправлены: точка внутри области тора, сторона сферической грани, перенос точки
грани. Серия 8: 337 с → 227 с, многогранных операций 68 → 48 (сумма их времени 140 с → 73 с). Остались: сетка конусной грани
со складкой (9), пустой результат (16, 10 с), многогранный операнд после многогранного шага, «отверстие между поясами» тора.

## 3в. Ещё отказы (2026-10-11, вторая половина дня)
Карта шара в классификаторе, складка разметки конусной шапки, отверстие между поясами тора. Серия 8: 227 → 202 с, многогранных
операций 48 → 33; серии 8–10: точный итог 493 из 549 непустых цепочек.

## 3г. Сопряжения: прямой построитель вместо резцов + булевой (2026-10-11)
Так делают промышленные ядра: скругление — правка B-rep по контактным линиям, а не вычитание резца. Замер в одном прогоне
(мс, прямой / резцы + булева): все 12 рёбер бруска R3 — 1036 / 16027; цепочка 3 рёбер — 236 / 1685; замкнутая цепочка —
230 / 1103; фаска всех рёбер — 3.6 / 167; угол фаской — 2.8 / 109. Остаток — разметка граней результата (90% времени), в ней
сферические углы: выбор полюса карты шара проверял «внутри грани» для каждого улучшения кандидата (891 проверка на 20 граней);
теперь кандидаты по возрастанию близости к краю, первый вне грани (20 проверок, тот же полюс; `KRN10-SPHERE-POLE-FAST`):
8 сферических углов 397 → 26.5 мс. Этот же выбор полюса работает в разметке и классификаторе любых сферических граней булевой.

## 3д. Цилиндр/цилиндр и квадрики: прямой построитель; уточнение сетки без повторных замеров (2026-10-12)

Скругление кромки поперечного отверстия d8 в валу R20 строит прямой построитель катящегося шара: 0.5–3 с вместо 25–40 с
обхода (протянутый резец, булева, многогранный результат). Измерено по разметке ленты у отверстия d30 (самый дорогой
случай): 19.2 с разметки, из них 18.7 с — уточнение (`Refine`). Каждый проход заново проецировал на поверхность центры ВСЕХ
треугольников, хотя меняются лишь соседи вставок. Годный треугольник запоминается по своим вершинам (те же точки и
параметры — тот же ответ): замеров отхода 1 283 045 → 42 867, уточнение 18.7 → 1.0 с, сетки побитно те же
(`P3D_REFINECACHE`, проверка — по счётчику в `KRN06-CYLCYL-ROLLING-BALL-EXACT`).

## 4. План (по измеренному вкладу)
1. ТОР В ТОЧНОМ МАРШРУТЕ — сделано (3а). Дальше — разобрать отказы точного маршрута на оставшихся 68 операциях серии 8.
2. ЛЕНИВАЯ РАЗМЕТКА В БУЛЕВОЙ: не размечать грани в «завершении», а при показе — с кэшем на грань (ключ по содержанию уже
   есть: `FaceMeshKey`); проверка разметкой — только у новых и изменённых граней.
3. ПРОИСХОЖДЕНИЕ КАК ВЫХОД ОПЕРАЦИИ (KRN-08, 08.2) и сохранение объектов нетронутых граней: операция сообщает
   «не тронута / изменена / разделена / новая»; история, подписи, аудит, нормализация — только для изменённых.
4. МНОГОГРАННЫЙ МАРШРУТ: фильтр плавающей точки перед рациональной арифметикой в предикатах разбиения; иерархия габаритов
   вместо полного разбиения; разметка тора — без поиска ориентации O(n²).
5. Цели скорости и памяти (ворота g.13) — задаёт пользователь; без них «быстро» не принимается.

## 2. Что сделано в r4

1. **Класс 2 повёрнутого скругления закрыт.** Первопричина: при округлении на сетку четыре угла повёрнутой
   прямоугольной грани не лежат в одной плоскости, и грань становилась двумя точными плоскостями — уже у исходного
   тела. Грани бруска ступеньки без контакта (стенка, дно) — так же. Следующая операция прижималась к одной копии.
   Метки 12063/12035 из передачи r3 — грани бруска ступеньки, а не резца скругления.
2. **`Kernel/Exact/ExactPlanarInput.cs`** — вход «одна плоская грань — одна точная плоскость» (из
   `ExactAdapter.ToExact`). Решение — в отдельном реестре; если все вершины остались на своих узлах (тела вдоль
   осей; есть ранний выход по осевым нормалям) — null и прежняя дорога побитово. Выключение: `P3D_PLANARINPUT=0`.
   Правила: вершины гранёных кривых граней остаются на узлах (иначе рвётся восстановление дуг: K01 S-ROUNDHOLE);
   грань, плоскость которой не выдерживается в какой-то вершине, теряет её, решение повторяется.
3. **`PlaneRegistry.FaceHints`** — истинные плоскости (нормаль, смещение в double) своих плоскостей граней;
   переносятся при `ExactSolid.Import`. Аналитически совпадающие (1e-7 мм) грани другого операнда в том же
   реестре получают ту же точную плоскость (FProbe Z angle=0.1 union=True: брусок с выдавливанием по оси Z идёт
   не контактным путём, а через ToExact).
4. **`ExactContactInput`**: своя плоскость грани резца без контакта — только в общем пути (`P3D_OWNPLANES=0` —
   выключить); местные источники в `TryAttach` — по кольцам с T-стыками (`ExactAdapter.Rings`).
5. **Воспроизводимость журналов K01**: ключи операций в проверках — по счётчику (`Feature.DeterministicKeys`,
   `P3D_DETERMINISTIC_KEYS`; K01Checks включает сам, `=0` — выключить). Два прогона allA совпадают полностью.
6. **Проверки**: FProbe — обязательный инвариант «после ступеньки у каждой плоской грани одна точная плоскость»
   (ловит возврат дефекта: 6 сценариев при выключенном исправлении); переменные `PLANARDBG`, `VCLUSTER`
   (`VCLUSTER2`), `LOOPDBG`; в `CONTACTDBG` — причины отказа кандидатов. K01 — режим `one <id>`.
   `tests/diffclass.py` — строгая классификация различий двух прогонов A06.

Ход поиска (FProbe rotations): своя плоскость резца везде — 80/88; только в пути скругления — 82/88; только
в общем пути — 84/88 (оставались сетки display); + ExactPlanarInput — 86/88 (Z angle=0.1 union); + местные
источники по кольцам и FaceHints — 88/88; + вершины кривых граней на узлах (K01 S-ROUNDHOLE) — 88/88, allA/B/S.

## 5. Известные ограничения (кратко)

См. `src/docs/release/KNOWN_LIMITATIONS.md` (раздел «Добавлено в обновлении 4»). Главное: проверка
самопересечений — по сетке, не по точному телу; точная булева — только «тело минус цилиндр»; точные рёбра пишутся
в STEP на копии тела; седловые вершины не поддержаны; Windows UI не проверен.

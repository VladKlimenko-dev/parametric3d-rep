# Дополнение к инструкции: этап UI — новое приложение на Avalonia UI (вместо WinForms)

Решение пользователя от 2026-10-11 (15:45, Магадан): интерфейс переделать целиком на Avalonia UI; организация работы, окна,
взаимодействие — по образцу Plasticity; операционные возможности параметрического моделирования — по образцу PTC Creo и
SolidWorks. Выполняется параллельно с этапом FF (`FREEFORM_STAGE.md`), начало — по распоряжению пользователя (как и FF: после
закрытия ворот ядра, если пользователь не решит начать раньше — работа над оболочкой от ядра не зависит).

## Что есть сейчас (замер 2026-10-11)
- Приложение: WinForms (`net8.0-windows`, `UseWindowsForms`), окно OpenTK.GLControl; UI + Views + Render ≈ 17 400 строк.
- Отрисовка (`src/Render`): собственный OpenGL-рендер (шейдеры, пакеты линий/точек/треугольников, кадровый буфер, камера,
  гизмо, размеры, ограничения эскиза) — переносим: от WinForms зависит только контрол-хозяин контекста.
- Ядро (`src/Kernel`) и модель (`src/Model`: документ, дерево операций, эскизы, параметры, конфигурации) от UI не зависят —
  переносятся без изменений.

## Рекомендации
1. «С нуля» — оболочка приложения, а не ядро и модель. Слои: Model (как есть) → ViewModel (новый, MVVM, команды, отмена/повтор)
   → View (Avalonia). Шина команд: каждое действие — команда с именем, горячей клавишей, иконкой, условием доступности,
   предпросмотром; меню, панели, палитра команд и горячие клавиши строятся из одного реестра.
2. Стек: Avalonia 11 (Fluent, своя тёмная/светлая тема), CommunityToolkit.Mvvm, Dock.Avalonia (стыкуемые панели),
   Svg.Controls.Skia.Avalonia (иконки SVG). 3D — `OpenGlControlBase` Avalonia с текущим рендером через привязки OpenTK.
3. 3D НЕ «бесшовно»: под Windows Avalonia по умолчанию даёт OpenGL ES 3.0 через ANGLE (Direct3D 11), а не настольный GL.
   Варианты: (а) шейдеры в подмножестве GLES 3.0 (работает везде); (б) режим WGL (`Win32PlatformOptions.RenderingMode`) —
   настольный GL, как сейчас. Рекомендую (а) + проверка (б) на машине пользователя. Позже — абстракция рендера (OpenGL сейчас,
   Vulkan/D3D при необходимости). Выбор/подсветка — по буферу идентификаторов (уже есть кадровый буфер).
4. Организация работы (Plasticity): окно — вид прежде всего; минимум рамок; палитра команд по поиску (Ctrl+Space / F3); всё —
   горячими клавишами; выбор — БЕЗ режимов (решение пользователя 2026-10-11, см. п. 4а); контекстная плавающая панель у выделения;
   круговое меню по правой кнопке; гизмо прямого перемещения/поворота/масштаба; операция — без модальных окон: параметры в
   боковой панели и прямо в виде (перетаскиваемые ручки размеров), живой предпросмотр, Enter — принять, Esc — отменить;
   привязки и подсказки к курсору; несколько видов/окон.
4а. ВЫБОР И КОНТЕКСТНЫЕ ДЕЙСТВИЯ (решение пользователя 2026-10-11). Отдельного переключателя «Вершина/Ребро/Грань/Тело»
   НЕТ. В 3D-виде курсор сам выбирает ближайший элемент под собой: вершину, ребро (кромку), грань/поверхность — с приоритетом
   по расстоянию в пикселях (вершина < ребро < грань) и предварительной подсветкой при наведении; Tab/колесо — перебор
   перекрывающихся кандидатов. Тело в 3D-виде НЕ выбирается: тело (деталь) и компонент выбираются в дереве сборки
   (Assembly) и деталей (Part); выбор в дереве подсвечивает тело в виде.
   Контекстные действия у выделения (плавающая панель, как в Plasticity), в РЕЖИМЕ ПАРАМЕТРИЧЕСКОГО МОДЕЛИРОВАНИЯ:
   - ребро или вершина → сразу фаска / скругление (вершина — скругление/фаска всех рёбер вершины), с ручкой размера в виде;
   - плоская грань → выдавливание (добавить/вырезать) или эскиз на этой грани;
   - неплоская поверхность → выдавливание (смещение грани);
   - тело (из дерева) → удалить; редактировать соединение (сопряжения) в сборке.
   Каждое действие создаёт операцию в дереве (правится и перестраивается), ссылки — устойчивые имена ядра (EdgeRef/FaceRef).
   В РЕЖИМЕ FREEFORM (этап FF) — весь набор Plasticity (прямое перемещение граней/рёбер/вершин, смещение, вытягивание,
   скругление, булевы, разрез, зеркало, массивы, кривые и поверхности по сечениям и т. д.; см. FREEFORM_STAGE.md).
   Ядру для этого нужно: выбор по лучу с иерархией вершина/ребро/грань (есть буфер идентификаторов вида) и устойчивые имена
   вершин (сейчас — у рёбер и граней).
5. Параметрическое моделирование (Creo/SolidWorks): дерево операций со строкой отката (rollback), подавление, перестановка,
   правка с перестроением; панель операции в духе Creo Dashboard / SolidWorks PropertyManager; эскизник с отображением и
   разбором конфликтов ограничений; отношения/уравнения и параметры; конфигурации (семейство таблиц); опорная геометрия;
   измерения и массовые свойства; разрезы; сборки с сопряжениями; позже — чертежи.
6. Порядок: U0 оболочка (окно, стыковка, тема, иконки, реестр команд, горячие клавиши, отмена/повтор); U1 перенос вида
   (контекст GL в Avalonia, камера, выбор, подсветка); U2 дерево + панель свойств + правка операций с предпросмотром;
   U3 эскизник; U4 инструменты прямого моделирования (вместе с FF); U5 сборки; U6 палитра команд, настройка, полировка.
   Старое WinForms-приложение живёт до паритета функций, затем удаляется.
7. Проверка: Avalonia.Headless — логика и снимки экрана без дисплея; 3D — под Xvfb с программным OpenGL (Mesa llvmpipe;
   в этой среде Xvfb, libGL, EGL есть) — снимки-эталоны вида. Проверка на Windows (ANGLE/WGL, драйверы, DPI) — у

## Предпросмотр и фоновое принятие (решение пользователя 2026-10-12)

- Правка операции (перетаскивание ручки, ввод размера): ядро строит ту же точную операцию в быстром режиме — без полной
  самопроверки тела и разметкой только изменённых граней; каждое новое движение прерывает прежнее построение
  (KernelContext, прерывание — ворота g.10). Предпросмотр рисуется отлично от принятого тела (g.11).
- Enter: сразу показывается результат предпросмотра; полная проверка (B-rep, сетка, объём, допуски) — в фоновом потоке;
  по её окончании тело принято; ошибка — операция в дереве красная с причиной, показ возвращается к последнему принятому телу.
  Ввод не блокируется.
- Перестройка дерева после правки ранней операции — в фоне, по порядку, с прерыванием следующей правкой; вид обновляется по
  мере готовности.
- Цель отклика (g.13): предпросмотр одной операции на детали до 25 операций — p95 ≤ 150 мс (цель 100 мс).
- Ядро: быстрый режим операции с мутацией и проверкой «принятое тело совпадает с предпросмотром» — готовится до этапа U2.

## Ход этапа: движок вида, операции, эскиз, параметры (2026-10-16, поставка u03)

По 17 замечаниям пользователя после u02. Ядро не тронуто; в модели — параметры по уровням (см. ниже).

- **Движок вида заменён** (`src/Render/Engine`; прежние RenderScene, LineBatch, PointBatch, TriBatch, Shaders, RenderStyles,
  GridRenderer, DimensionRenderer и др. удалены). Сцена собирается на процессоре только при изменении модели
  (`SceneBuilder`), кадр — `SceneRenderer`: MSAA до 8×, фон-градиент, студийный свет с гаммой, контур силуэта,
  рёбра постоянной ширины со сглаживанием, штрих невидимых линий, точки (круг, квадрат, ромб). Подсветка — текстура
  признаков по номерам выбора (без перестройки сетки). **Выбор под курсором — проходом выбора видеокарты** (один пиксель
  в окрестности курсора): прежний перебор всех треугольников на процессоре при каждом движении мыши — вероятная причина
  зависаний вида — убран (остался только для проверок без OpenGL). Перестроение модели запускается из потока окна.
- Стили: тонированный, **тонированный с рёбрами (по умолчанию)**, каркас, невидимые линии штрихом, прозрачный.
  **Рёбра и вершины тела выбираются во всех стилях** (вершины — крайние точки тела, видны при наведении и выборе).
- Верхняя полоса: «Параметры», «Свойства» (повторный щелчок скрывает панель, крестика нет), тема и **язык EN/RU**
  (`App/Localization`: строки в коде по-русски через `L()`, перевод — `Strings.En`; выбор хранится в `ui.json`).
- Панель вида: «Вписать», **одна кнопка проекции** (Персп./Орто — щелчок переключает), стиль (список), **«Опорные» со
  стрелкой** — список-флажки: плоскости, оси, начало координат, точки, линии, вершины, осевые, эскизы, размеры,
  обозначения, измерения. Кнопки видов спереди/сверху/справа убраны (куб вида; в палитре команды остались).
- Куб вида: «Домой», повороты и стрелки ловятся всей площадью кнопки, а не контуром значка.
- **Полоса операций слева**: Эскиз; Выдавливание, Вырез, Вращение; Отверстие, Скругление, Фаска, Скругление вершины,
  Оболочка; Плоскость; Зеркало, Линейный и Круговой массив. В режиме эскиза — инструменты эскиза.
- **Полоса выбора внизу вида (как в Plasticity)**: что выбрано и подходящие операции (грань — эскиз, выдавливание,
  плоскость, зеркало, отверстие, оболочка; ребро — скругление, фаска, массив; вершина — скругление и фаска вершины;
  эскиз — выдавливание, вырез, вращение, правка; операция — изменить, подавить, удалить). Во время операции — «ОК» и
  «Отмена».
- **Операции в правой панели** с живым предпросмотром: операция добавляется в деталь сразу, поля (число или формула с
  параметрами, ↑↓ — шаг) и ссылки (рёбра, грань, плоскость, эскиз, ось — из выбора до команды и щелчками по модели)
  перестраивают деталь в фоне; «ОК» — один шаг отмены, «Отмена» — деталь как была. Двойной щелчок по операции в дереве —

## Аварийное завершение под Windows (2026-10-16, поставка u06)

Пользователь: приложение зависло и завершилось с кодом 0xC0000374 (STATUS_HEAP_CORRUPTION — порча кучи в машинном коде).
Управляемый код ядра и модели машинную кучу испортить не может (небезопасного кода там нет, только `stackalloc` с
проверкой границ). Значит, причина — в машинной части: драйвер OpenGL или его связка с отрисовкой окна.

- Наиболее вероятная причина: настольный OpenGL (WGL) на Intel Iris Xe, где Avalonia рисует окно через Skia в том же
  OpenGL, а вид — в общем с ним контексте. Сама Avalonia под Windows по умолчанию использует ANGLE (OpenGL ES 3 поверх
  Direct3D 11) — именно из-за таких драйверов. **По умолчанию теперь ANGLE**; WGL — по выбору: меню «Файл → Графика»,
  параметр `--gl angle|wgl|software`, переменная `P3D_GL` (со следующего запуска).
- Путь OpenGL ES проверен здесь: шейдеры в виде GLSL ES 3.00 (`--dump-shaders папка`) компилируются и связываются в
  настоящем контексте OpenGL ES 3 (Mesa EGL); добавлена точность для выборок. Перенос сглаженного кадра в окно — через
  свой буфер того же формата (в ES перенос из многовыборочного буфера в буфер другого формата запрещён, вид был бы пуст).
- Новый контекст OpenGL (потеря, пересоздание окна) — новый рисовальщик: номера объектов старого контекста больше не
  удаляются в новом (там это были бы чужие объекты).
- След для разбора: в журнал (`%LOCALAPPDATA%\Parametric3D\app.log`) пишутся запуск (поставка, режим графики, ОС),
  каждая команда, создание/потеря/уничтожение контекста OpenGL, поток отрисовки, выход. Метка `running.flag`: если
  прошлый запуск не дошёл до выхода, это записывается в журнал и показывается при следующем запуске. Режим графики и
  поток отрисовки — в отчёте «Теста».
- Проверено у пользователя (u06, `logs/win01/P3D_test_20261016_141459_angle.txt`): ANGLE 2.1 поверх Direct3D 11 на Intel Iris Xe,
  OpenGL ES 3.0; зависаний и аварий нет; 28 из 28 проверок, 11 из 11 целей; наибольшая остановка окна 128 мс. Вид
  2286×1308 со сглаживанием 8×: 33–36 кадров/с при 0.4 мс кадра на процессоре — предел видеокарты (выбор под курсором
  31 мс — один-два кадра); резерв — сглаживание 4× на встроенной графике.

## Эскиз, ссылки, размеры, ручки, цепочки рёбер (2026-10-16, поставка u07)

По замечаниям пользователя после u06.

- **Эскиз без тела (1.1)**: в режиме эскиза тела не рисуются и не заслоняют эскиз — их рёбра и вершины видны тонкими
  линиями поверх (`SceneRenderer.SketchMode`), выбор тоже без заслонения. Сетка больше не закрывает линии эскиза.
- **Ссылки эскиза (2.2–2.3, как References в Creo)**: кнопка «Ссылки» в полосе эскиза — панель со списком ссылок и
  удалением; рёбра и вершины детали подсвечиваются под курсором, щелчок (без инструмента или при открытой панели)
  проецирует их в эскиз как ссылочную геометрию (`App/Sketching/EdgeProjection.cs`: отрезок, окружность, дуга, ломаная).
  Привязка инструментов ловит и точки ссылок.
- **Размеры (2.4)**: после каждого готового примитива — размеры по умолчанию (`Model/Sketching/DefaultDimensions`,
  как в прежнем приложении): собственные размеры фигур, углы, расстояния до соседей, затем **до ссылок** (перпендикуляр
  до прямой ссылки, до вершины или центра) и в конце — от нуля эскиза; вместе они определяют эскиз полностью
  (проверка: 0 степеней свободы). Размеры рисуются (перенесён прежний `DimensionRenderer` → `SketchDimensions`, подписи
  читаются при любом повороте вида); двойной щелчок по размеру — новое значение или формула, размер становится
  управляющим (противоречащий — отклоняется). Эскиз на грани: начало — проекция начала координат детали.
- **Отмена без «пропадания» детали (2)**: «Отмена» новой операции, плоскости, нового эскиза убирает их из детали на
  месте (деталь не заменяется снимком, расчёт идёт от сохранённого состояния); правка готовой — снимком, но вид держит
  прежнюю деталь, пока новая не посчитана (`HoldSceneUntilBuilt`).
- **Глаз элемента независим от детали (3)**: скрытая деталь прячет своё тело; её эскизы, плоскости, оси видны по своему глазу.
- **Касательные цепочки (4)**: щелчок по ребру выбирает и касательно продолжающие рёбра (`Topo.TangentChain`, Alt —
  одно ребро); фаска по цепочке «прямое — дуга скругления — прямое» строится годным телом (проверка).
- **Свойства операций (5)**: фаска — тип (равные катеты, два катета, катет и угол) с нужными полями; выдавливание —
  «до следующей грани», вторая сторона; скругление — переменный радиус; вращение — начальный угол; отверстие — поля по
  виду (угол зенковки). Поля показываются по условию.
- **Ручки как в Plasticity (6)**: у выбранного ребра, вершины, грани — стрелка наружу и внутрь; тянут за конец:
  ребро — наружу фаска, внутрь скругление; вершина — фаска угла / скругление вершины; плоская грань — наружу
  выдавливание контура грани, внутрь вырез; кривая поверхность — внутрь оболочка. Величина — расстояние вдоль стрелки,
  операция открывается в панели с предпросмотром.
- **Ctrl (7)**: Ctrl+щелчок добавляет, повторный — убирает; Shift — добавляет.
- Проверки: `tests/ui` — 16 из 16 (новые: касательная цепочка и фаска по ней, ссылки и полная определённость эскиза,
  отмена без замены детали, Ctrl).

## Как считано

- **Шкала:** в каждой строке уровень Parasolid — **100 %**. Это эталон промышленного ядра (NX, Solid Edge, SolidWorks и др.).
  Больше 100 % — мы в этом лучше Parasolid, причём это доказано нашими проверками.
- **Parametric3D:** по коду, проверкам и журналам — `KERNEL_SUPPORT_MATRIX.md`, CHANGELOG k27–k171, корпуса `loftseq`,
  `loftcorpus140`, серии случайных булевых с OpenCascade.
- **OCCT 8.0.1:** по примечаниям к выпускам, документации и нашим разностным прогонам против OCCT (`tools/occt_*.py`).
- **Parasolid v39.0:** по описаниям выпусков Siemens. Исходники закрыты и замеров на одной машине нет — его скорость и
  детерминизм не измерены, а приняты за 100.
- Проценты — экспертная оценка «ширина возможности × надёжность на корпусе», а не счёт пунктов. Итог — среднее по группам,
  чтобы группа с многими строками не перевешивала.
- **Не входит:** приложение (Creo, SolidWorks, QymCAD — отдельный разбор), трансляторы чужих форматов (Parasolid продаёт их
  отдельно), а также FEA и расчётная сетка — их нет в ядре ни у Parasolid, ни у OCCT.

Parametric3D сейчас — **≈ 68 %** уровня Parasolid. OCCT — ≈ 75 %. По строкам: лучше Parasolid — 4, наравне — 10,
хуже — 22.

**Где мы впереди уже сейчас:** модельная точность, оценка погрешности масс-свойств, проверка каждой операции и честный
отказ вместо негодного тела, точные касания. Это и есть заявленная разница «точнее и надёжнее», но пока — в узких местах.

**Где отстаём сильнее всего:**

- общие (немногообразные, ячеистые) тела;
- скругления граней и сложные углы скруглений;
- прямое редактирование и лечение импорта;
- смешанные модели «сетка + B-rep», решётки;
- скорость (≈ 1.7–1.9× медленнее OCCT на булевых);
- открытый программный интерфейс.

## Где мы лучше — и чем это доказано

1. **Точность модели.**
   - У нас 1e-7 мм и 1e-12 рад. У Parasolid — 1e-5 мм и 1e-11 рад. У OCCT допуск совпадения (Confusion) — 1e-7 единицы, но
     в операциях допуски рёбер растут, а для почти совпадающих тел нужен режим fuzzy.
   - Объём на аналитическом пути — ошибка 0…3e-11 мм³. Деталь, сдвинутая на 499 м, — 1.9e-14 относительной ошибки.
   - **Оговорка:** пересечения поверхностей, сшивка и многогранный путь у края габарита ещё не проверены.
2. **Масс-свойства с границей ошибки.** У каждого числа — оценка погрешности. 52 тела против OCCT — ни одного выхода за
   границу.
3. **Проверка каждой операции.** Тело проверяется по B-rep, по сетке и согласием с CSG. Негодное не принимается: операция
   отказывает с причиной. У OCCT `BRepCheck_Analyzer` вызывает приложение, если захочет, и невалидный результат может выйти
   из операции. Цена гарантии — время: проверки идут в фоне после показа (k126).
4. **Касания.** Касание по точке и окружности идёт точным маршрутом, без режима fuzzy. Совпадающие поверхности сливаются с
   доказательством площадью.

## Скорость (замеры)

- **18 булевых детали пользователя** (k126, 2 ядра): у нас 0.6 с, у OCCT 0.32–0.36 с. Объём совпал до 0.01 мм³.
- **Сетка итогового тела:** у нас 0.48 с, у OCCT 0.11 с. Наша плотнее и с доводкой качества.
- **Медиана «B-rep против B-rep»** (ворота g.13, krn10q): 2.17× от OCCT.
- **Почему мы медленнее** (`OCCT_COMPARISON.md`): разметка граней внутри операций, независимые проверки, нет общих
  подформ.

### Приложение

| № | Цель | Критерий закрытия |
|---|---|---|
| П1 | **Деталь** | все операции ядра в панели с предпросмотром (U3–U6); отмена везде; открытие и правка без перестроения |
| П2 | **Сборка** | сопряжения и кинематика, состояния сборки (положения деталей), зазоры и пересечения, BOM, внешние ссылки на файлы (BACKLOG e) |
| П3 | **Чертёж** | ассоциативность (правка модели → чертёж, правка размера с листа → модель), спецификация как документ, ГОСТ и ASME Y14.5 полностью |
| П4 | **Построение по описанию** | создание операций через MCP; дерево операций JSON → деталь → проверки; первый класс — переводник (STRATEGY, «Порядок классов деталей») |
| П5 | **Паспорт изделия из модели** | масса, площади поршней, ходы, минимальное сечение, огибающая пакера — первая практическая функция направления |
| П6 | **Расчёт** | осесимметричная FEA тел вращения со сверкой по API TR 5C3 / ISO 10400; затем циклическая симметрия и 3D |

**Порядок:** Я1 → Я2 и Я3 → П4 и Я8 → П5 → Я4 → П6 → остальное по необходимости. Я1 — первым, потому что генератор
вариантов (STRATEGY, этап 1) без детерминизма даёт мусор для расчёта и обучения.

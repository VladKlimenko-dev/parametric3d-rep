# Parametric3D: локальные проверки резьбы и allA/allB/allC

## Цели

Глобальная цель: CAD должен создавать проверяемую геометрию, а не принимать изображение за точное тело. Для резьбы это означает независимость B-rep от экранной сетки, явный отказ от неподдержанного точного выреза и быстрое взаимодействие с панелью.

Практическая цель текущих изменений: подключить присланный каталог, отделить лёгкий предпросмотр от окончательного построения, начать движение резца до торца и собирать постоянную резьбу из одного витка с общими рёбрами стыков, без общего Boolean. Остаточный неполный виток или непериодическое окончание с плавным выходом строятся отдельно; полная квалификация всех типов резьбы остаётся отдельной задачей.

Подтверждённый быстрый путь: наружная неконическая резьба на отдельном цилиндре без дополнительных граней. Для воспроизведения выхода создайте единственный цилиндр Ø6 мм длиной 5 мм, выберите M6 coarse, снимите «Косметическая», включите «Плавный выход» и задайте длину 3,25 мм: канавка должна плавно закончиться до противоположного торца. Без выхода проверен путь на полную длину цилиндра; слишком короткий точный выход должен отказать, сохранив заготовку.

## Запуск на вашем компьютере

Для всех трёх групп двойным щелчком запустите `regress_allABC.bat` из корня проекта. Он последовательно запускает allB, allA и allC на текущей версии, без автоматического `git pull`; обновление выполняйте отдельно до начала прогона. При запуске из консоли можно передать `-Parallel`, но для сравнения времени предпочтителен последовательный режим. Сам BAT в Linux-среде не исполнялся: Windows-проверку нужно выполнить локально.

Режим `-Only thread` теперь запускает и `threadchecks`, и `threadexit`. Вторая группа отдельно проверяет точный плавный выход, копирование ячеек, независимый объём, касательность, сохранение B-rep и атомарность отказов.

Проверки выполняются локально и сами по себе не обращаются к языковой модели. Полные allA/allB/allC можно выполнять у себя и затем прислать результаты; здесь достаточно адресных проверок исправлений.

Нужны Windows, .NET 8 SDK с runtime .NET 8, полный checkout репозитория и доступ к NuGet при первой сборке. Более новый SDK допустим, но для запуска target net8.0 нужен соответствующий runtime; наличие одного SDK новой версии не гарантирует запуск. В каталоге проекта должны быть `src`, `tests`, `threads_db.json`, `threads_table.csv`, а также тестовые данные `tests/k01/data` и `tests/ui/data`; неполный sparse-checkout не подтверждает полный корпус.

Скрипт PowerShell проверен по коду, но в этой Linux-среде не запускался. Проверены сборка ядра и перечисленные в `THREAD_IMPLEMENTATION_STATUS.md` адресные режимы.

Сначала сохраните свои незакоммиченные изменения, затем обновите проект и запустите:

```powershell
git pull --ff-only
git rev-parse HEAD
powershell -NoProfile -ExecutionPolicy Bypass -File .\regress.ps1 -Only thread -NoPull
powershell -NoProfile -ExecutionPolicy Bypass -File .\regress.ps1 -Only abc -NoPull
```

`-NoPull` фиксирует одну версию на время серии. Режим `abc` включает все три этапа, последовательно; первоначально рекомендуется именно последовательный запуск, чтобы сравнивать времена без конкуренции за процессор и память.

Для отдельных прогонов:

```powershell
.\regress.ps1 -Only allA -NoPull
.\regress.ps1 -Only allB -NoPull
.\regress.ps1 -Only allC -NoPull
```

После завершения скрипт ждёт Enter, чтобы окно не закрылось. Если вы прервали этап, его неполный лог тоже полезен, но это не успешный полный прогон.

Скрипт записывает stderr и коды процессов, отдельно проверяет `ALLC-SUMMARY` и возвращает ненулевой код при обнаруженном отказе или неполном итоге. В диагностике allC нельзя принимать строку `passed:0,failed:0` за успешный прогон.

## Что прислать

После завершения прогонов старые `logs/regress_*` можно удалять, предварительно сохранив нужные отчёты и модели отказов. Не очищайте активный прогон; всю папку `logs` не удаляйте вслепую, поскольку в репозитории есть отслеживаемые исторические baseline-материалы. Очистка этих материалов является отдельным изменением Git.

Архивируйте целиком соответствующие папки `logs/regress_<дата_время>`, а не только последние строки. Внутри нужны следующие материалы:

- **SUMMARY.txt:** версия, сводки этапов и коды завершения процессов.
- **Все .log и .err:** результаты, исключения и причины отказов.
- **allC_models:** сохранённые модели неудачных случаев, если такие возникли.
- **dotnet-info.txt, git-status.txt, test-settings.txt:** среда, состояние checkout и активные настройки проверок.
- **Дополнение от вас:** CPU, объём RAM, версия Windows, был ли запуск прерван; для UI также модель `.p3d`, параметры резьбы и снимок проблемы.

Для упаковки последнего запуска:

```powershell
$run = Get-ChildItem .\logs -Directory -Filter 'regress_*' |
    Sort-Object LastWriteTime -Descending | Select-Object -First 1
Compress-Archive -Path $run.FullName -DestinationPath ($run.FullName + '.zip')
```

Если запускались отдельно `thread` и `abc`, пришлите обе папки. Не запускайте другую сборку этих тестов одновременно: скрипт использует общий временный каталог исполняемых файлов.

## Как читать результаты

- **allA/allB:** проверяйте итоговые `passed/failed`, код процесса и наличие завершённого итога.
- **allC:** главный итог находится в записи `ALLC-SUMMARY`, поля `fail`, `warn`, `slow`, `steps`; общий `passed:0,failed:0` сам по себе ничего не доказывает.
- **Неполный прогон:** отсутствие итоговой записи, авария или прерывание не считаются успехом.
- **Фильтры и мутации:** `P3D_ALLC_ONLY` ограничивает корпус; экспериментальные `P3D_*` могут менять алгоритмы. Для квалификационного прогона уберите ранее заданные экспериментальные переменные, а настройки из отчёта сохраните.
- **Предпросмотр:** измерение `threadbench preview` относится к построению линий в ядре, не к полному времени кадра Avalonia.

## Ограничения каталога

Таблицы пользователя задают номинальные размеры и многоугольные профили. Они не содержат полей допусков 6g/6H и не доказывают соответствие каждой кривой стандарту; название семейства ROUND само по себе не превращает многоугольник в округлённый нормативный профиль.

Быстрый предпросмотр показывает винтовые линии, траекторию захода и начальное сечение, не изменяя тело. Окончательное построение запускается по ОК и должно либо вернуть проверенное B-rep, либо явно сообщить об отказе, без незаметной подмены гранёным телом.

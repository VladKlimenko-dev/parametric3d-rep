# Parametric3D: обновление из src.zip и сверка проекта

Исходники обновлены из последнего архива пользователя, документация приведена к текущей структуре, старые ZIP ядра удалены по отдельному запросу. Аудит выявил и исправил одну регрессию нового кода резьбы; полная промышленная квалификация и проверка Windows/UI этим обновлением не заявляются.

Дополнение после первоначальной синхронизации: пользователь передал `threads_db.json` и `threads_table.csv`, они добавлены в проект. Упоминания отсутствующих таблиц ниже относятся к моменту импорта `src.zip`; текущее состояние резьбы, реализованный повтор витков и оставшиеся ограничения описаны в `THREAD_IMPLEMENTATION_STATUS.md`.

- **Репозиторий:** `VladKlimenko-dev/parametric3d-rep`, ветка `main`.
- **Исходный HEAD:** `07668ed756c7b74f9ad630a8236c3cf867b5b14a`.
- **Архив:** `src.zip`, SHA-256 `6d3b736902efb3ff3d63ed83ea7b8d438ab49f0e44964126b5a009abcb74795f`.
- **Состав:** 893 файла, из них 25 генерируемых файлов `obj` не перенесены; оставшиеся 868 файлов относятся к исходникам, ресурсам и документам.
- **Область:** архив содержит только `src`, поэтому корневые тесты, скрипты, CI, корпуса и журналы не удалялись из-за их отсутствия в ZIP.

Сравнение с Git показало 9 новых файлов и 8 содержательно изменённых; 848 существующих файлов отличались только CRLF/LF, ещё 3 совпадали побайтно. Переводы строк приведены к существующему LF, без изменения содержания этих 848 файлов.

После переноса и исправления проверено соответствие исходных `.cs`, `.csproj`, `.axaml`, `.svg`, `.tsv`, `.xlsx` архиву с учётом переводов строк. Единственное дополнительное отличие в этом наборе: исправленный `src/Model/Threads/ThreadDb.cs`; документация сознательно переработана.

### Дополнительное исправление

Первый прогон обнаружил отказ `G5-GLOBALS-INVENTORY`: новые статические `ThreadDb.LoadError` и `_byId` изменяются вне контекста ядра. Помимо нарушения существующего контракта, индекс инициализировался отдельно при обращении из потоков.

Каталог, индекс и диагностика теперь публикуются совместно через один `Lazy<Catalog>` с `ExecutionAndPublication`. Список и словарь имеют read-only оболочки; это не утверждение о глубокой неизменяемости всех полей `ThreadSpec`.

Повторная группа `guarantees`, включая G5, проходит. Добавлены шесть тестов в существующий проект `tests/k01`, без создания ещё одного проекта приложения или ядра.

## Очистка

- **Архивы:** удалены все 16 `archive/kernel_k*.zip`, от k171 до k185h, суммарно 27 916 849 байт в текущем дереве; остальные материалы не удалены. Добавлено исключение для новых таких ZIP и обновлён `archive/README.md`.
- **Старые инструкции:** удалены `src/HANDOFF.md` и `src/SOSTOYANIE.md`; устаревшие WinForms-разделы `src/README.md` и старая карта `src/ARCHITECTURE.md` заменены актуальными.
- **Дубли MD:** 21 корневой документ заменён коротким указателем на полную редакцию в `src/docs/release`. Более новые корневые BACKLOG, CHANGELOG и KERNEL_COMPARISON сначала перенесены туда; в FREEFORM, UI-плане, KNOWN_LIMITATIONS и KRN10 сохранены более полные редакции из `src`.
- **Не потерянные обязательства:** технические уроки и незакрытые категории работ вынесены в `REQUIREMENTS_REVIEW.md`. Исторические тексты доступны в Git.
- **Сохранённые материалы:** тестовые проекты, пользовательские fixtures, `.github`, `tools`, журналы и версия отдельной FEA-библиотеки не удалялись и не смешивались с этим обновлением.

Удаление ZIP из `main` не вычищает их из прежних коммитов и не уменьшает автоматически размер всей Git-истории. Переписывание истории и force-push не выполнялись; исторические упоминания архивов в CHANGELOG обозначают прежние состояния.

## Сверка Markdown

Обновлена карта `src/ARCHITECTURE.md`: сущности B-rep, геометрия, результаты операций и гарантии, модель документа, дерево фич, параметры, сессия, рендер, выбор, обмен, чертежи, резьба и граница с FEA. Подтверждённые устаревшие пункты отмечены выполненными в `REQUIREMENTS_REVIEW.md`, но частные незакрытые случаи не объявлены решёнными.

Инструмент `tools/audit_docs.py` просмотрел 53 доступных Markdown-файла, исключая созданные отчёты аудита и `archive`. Реестр `audit/2026-11-11/requirements.tsv` содержит 212 уникальных записей: 73 исходно отмеченные выполненными, 61 открытый checkbox и 78 текстовых записей для проверки; точные дубли объединены с сохранением происхождения.

Эти 73 отметки не являются 73 свежими подтверждениями. Автоматическая опись не распознаёт семантику каждого пункта всех старых планов; ручные заключения и конкретные основания находятся в `REQUIREMENTS_REVIEW.md`, всё остальное оставлено явно неподтверждённым.

### Незавершённые прогоны

Первоначальные `allA` и `allB` остановлены по лимиту 480 секунд каждый, без итогового полного результата. До остановки в логах было 140 записей тестов allA (137 успешных, 3 отказа) и 57 allB (46 успешных, 11 отказов).

Один отказ был описанной регрессией G5, исправленной и перепроверенной. Остальные 13 сообщений об отказе относились к отсутствующим fixtures разреженного checkout, а не к установленной ошибке геометрии; `quarter_cyl.step` и `user_k116.p3d` затем восстановлены точечно из Git, группа `query` повторно прошла. Полные allA/allB после этого не объявляются пройденными.

Полный UI/Avalonia, Windows/GL и большой корпус импортов не проверены. Среда имела около 0.2 ГБ свободного диска, UI-пакеты не были восстановлены; вместо рискованной большой сборки выполнена локальная headless-проверка, ограничения которой явно сохранены.

### Воспроизведение

Из корня полного checkout:

```sh
dotnet build tests/k01/K01Checks.csproj -c Release \
  -p:LocalDeps="$PWD/tools/deps" -p:LangVersion=12

DOTNET_TieredCompilation=0 DOTNET_ROLL_FORWARD=Major \
  dotnet tests/k01/bin/Release/net8.0/K01Checks.dll guarantees
DOTNET_TieredCompilation=0 DOTNET_ROLL_FORWARD=Major \
  dotnet tests/k01/bin/Release/net8.0/K01Checks.dll threadarchive
DOTNET_TieredCompilation=0 DOTNET_ROLL_FORWARD=Major \
  dotnet tests/k01/bin/Release/net8.0/K01Checks.dll negative
DOTNET_TieredCompilation=0 DOTNET_ROLL_FORWARD=Major \
  dotnet tests/k01/bin/Release/net8.0/K01Checks.dll query

python tools/audit_docs.py --output docs/audit/2026-11-11/requirements.tsv
```

При установленном .NET 8 runtime принудительный roll-forward не требуется. Логи финальных групп и сборки сохранены рядом с реестром в `audit/2026-11-11`; первоначальные неполные логи имеют отдельные имена.

## Следующие действия

- **Комплектность резьбы:** получить настоящие JSON/CSV-таблицы, затем проверить все геометрические режимы и панель.
- **Регрессия:** на полном checkout закончить allA/allB, пользовательские последовательности и UI; отдельно проверить Windows под нагрузкой.
- **Архитектура:** использовать новую карту как навигацию, а BACKLOG как список открытых пользовательских замечаний.
- **Статусы:** закрывать пункты по воспроизводимому результату, не по наличию старого `[x]`, процента или класса с подходящим названием.
